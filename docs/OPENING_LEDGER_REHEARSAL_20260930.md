# Opening ledger rehearsal control

The Accounting workspace now supports a separate, non-posting target-ledger opening package. A finance maker supplies a cutoff date, named source and SHA-256, full GL trial balance, per-party AR/AP and advance controls, and an independently referenced stock valuation. The package fails closed unless all GL accounts are active/postable, debits equal credits, and trade receivables (1200), trade payables (2100), supplier advances (1210), customer advances (2140), and inventory (1300) equal their supporting totals. Duplicate accounts/party controls and invalid monetary values are rejected.

The evidence is fingerprinted and reviewer decisions require a different identity and the current revision. `approved_rehearsal` means the supplied arithmetic was independently reviewed; it never means final opening balances are certified. No opening journal is posted, and neither preview has posting enabled. Existing non-atomic BizModo AR/AP import controls remain test evidence, not a source of opening GL truth.

Before cutover, freeze BizModo transactions, make one fresh read-only atomic capture, verify file checksums against actual files, reconcile source leaf-account trial balance and independently evidenced party/stock valuations, resolve every variance, obtain named finance/warehouse acceptance, and only then design and validate a one-time idempotent opening posting and financial-statement carry-forward. The current UI accepts a declared source checksum and stock total; it does **not** verify the underlying files, stock lots/cost layers, or source accounting accuracy. Therefore `opening_balances_certified` remains false in reports and in this package API.
